# 扩展与边界

加一条工作流不用碰程序——写一份 YAML 放工作流目录就行，这是这个程序的主要扩展方式。其余几处：

- 加动作：在动作层写一个函数返回 `Result`，在入口注册子命令与选项。算法只落一次。
- 加判据种类：在判据层加一种判法，同时在 schema 的判据字段里认它；两处同步。
- 改记录段位：段位与模板在记录层一处，改这里，报告与日志都跟着变。
- 接 provider：这是另一条轴，落在入口与一个独立的接口层，不动本地的定义、任务与判据。
- 开窗口：窗口与命令行共用动作层的 `Result`，窗口只负责画，不重写算法。

定义用 YAML、记录用 Markdown：定义要意义固定，字段与取值由 schema 挡；记录要读得顺，报告与日志是人能直接看的文件。

只写自己造的文件，不改工作区里别人的内容。不做服务端、不做数据库。不为以后可能用到的字段提前留位——材料四字段、判据四判法都是够用即止，多了就是负担。
