# 扩展与边界

加一条工作流不用碰程序——写一份 YAML 放工作流目录就行，这是主要扩展方式。其余几处：

- 加动作：在对应聚合写一个函数返回 `Outcome`，在入口（`cli/`）注册子命令与选项。算法只落一次。
- 加判据种类：在工具箱 `quanttide_work::criterion` 加一种判法，同时在本侧 [audit](audit.md) 认它；两处同步。
- 接 provider：另一条轴，落在入口与 [adapter](adapter.md) 的 `health`，不动本地的定义、任务与判据。
- 开窗口：窗口与命令行共用动作算出的 `Outcome`，窗口只负责画，不重写算法。

定义用 YAML、记录用 Markdown：定义要意义固定，字段与取值由 schema 挡；记录要读得顺，是人能直接看的文件。

只写自己造的文件，不改工作区里别人的内容。不做服务端、不做数据库。不为以后可能用到的字段提前留位——材料四字段、判据四判法都是够用即止。
