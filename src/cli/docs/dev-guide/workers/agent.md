# AgentWorker：走一步的执行器

`AgentWorker` 是 `src/workers/agent.rs` 里的一个结构体，负责把工单的一步交给 AI 并收回结果。它是 [workers](index.md) 这一层的主角。

## 它拿什么、不拿什么

只拿一个工作区（`LocalWorkspace`，里面是三处路径）。不拿工单——工单是每次调用时传进来的。

为什么不拿工单：如果它自己存一份，就得分清楚「我改的是我这份还是账上那份」，那正是它不该操心的。传进来、用完就还，边界干净。

## 四个动作

`execute` 是主入口，把一步拆成四件事：

1. `build_context` 组装现场：从工单和这一步凑出话术要的数据——工单名、描述、全部步骤、这一步做什么、报告与日志的路径、前几笔流水；同时把判据里的占位（比如 `{{report}}`）换成本趟的真路径。
2. `invoke_ai` 交给 `pi`：跑一趟，收回输出，顺手取最后一行当「一句话摘要」。
3. `judge` 审：这一步有 agent 判据时，让 `pi` 按这些判据逐条答，每条认回「说明 / 结论 / 理由」。
4. `record` 记：核程序判据、记账，把结果包成命令行要的信封（过没过、屏幕上的话、表格、结构化数据）。

## 动作出口 order_next

`execute` 只管「一步」，`order_next` 管「从命令到这一步」：

1. 按名字打开工单；
2. 算出下一步——第一个没走过的站；都走过了就报「所有步骤都走过了」；
3. 这一步是给人做的，不替人做，提示「轮到你」并让用 `order done` 记；
4. 其余交给 `execute`。

## 它不做什么

- 不改工单字段：记账调 `crate::order::execute`，由工单聚合自己的方法落；
- 不发事件：`WorkRecorded` 由工单聚合自己发；
- 不定判据怎么判：判据的模型在 `crate::criterion`，跑程序判据在 `crate::order::rules`；
- 不写话术：给智能体的两段话在 `crate::prompts`。

最要紧的一条：不碰 `crate::order::events`。事件归聚合，执行器只交结果。

## 跟着测试读

`tests/order_next.rs` 是最好的入门读本，一趟一个情形：`pi` 跑成记账、跑不成不记、审查 ✗ 照记、重走追加。对着它读 `execute` 的四步，很快能对上号。
