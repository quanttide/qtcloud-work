# AgentWorker：走一步的执行器

`AgentWorker` 是 `src/workers/agent.rs` 里的一个结构体，负责把工单的一步交给 AI 并收回结果。它是 [workers](index.md) 这一层的主角。

## 它拿什么、不拿什么

只拿工作区根（一条路径）。不拿工单——工单是每次调用时传进来的；也不管「下一步是哪一步」，那是调用方的事。

为什么不拿工单：如果它自己存一份，就得分清楚「我改的是我这份还是账上那份」，那正是它不该操心的。传进来、用完就还，边界干净。

## 四个动作

入口 `run` 把一步拆成四件事，挨个调：

1. `plan` 组装现场：从工单和这一步凑出话术要的数据——工单名、描述、全部步骤、这一步做什么、报告与日志的路径、前几笔流水；同时把判据里的占位（比如 `{{report}}`）换成本趟的真路径。
2. `execute` 交给 `pi`：跑一趟，收回输出，顺手取最后一行当「一句话摘要」。
3. `evaluate` 审：这一步有 agent 判据时，让 `pi` 按这些判据逐条答，每条认回「说明 / 结论 / 理由」。
4. `record` 记：核程序判据、记账（走 `Order::record_step_result`），把结果包成命令行要的信封（过没过、屏幕上的话、表格、结构化数据）。

## 从命令到一步

开单、认下一步、判断这一步给人还是给 AI、打发人做的——这些在调用方（`cli/handlers/command.rs` 的 `order_next`）。`AgentWorker` 只接最后那半：给一步，走完。

## 它不做什么

- 不改工单字段：记账走 `Order::record_step_result`，由工单聚合自己的方法落；
- 不发事件：`WorkRecorded` 由工单聚合自己发；
- 不定判据怎么判：判据的模型在 `crate::criterion`，跑程序判据在 `crate::order::rules`；
- 不认下一步、不挑活：那在调用方。

最要紧的一条：不碰 `crate::order::events`。事件归聚合，执行器只交结果。

## 跟着测试读

`tests/order_next.rs` 是最好的入门读本，一趟一个情形：`pi` 跑成记账、跑不成不记、审查 ✗ 照记、重走追加。对着它读 `run` 的四步，很快能对上号。
