# workers：把一步交给智能体

## 先看这个项目在干什么

qtcloud-work 是个命令行工具，把一件事拆成一条步骤清单来跑。三个词先记住：

- 工作流是清单：一串步骤，比如「问候 → 起草 → 收尾」；每步写着做什么、谁做、怎么算完。
- 工单是行程：照着一张工作流走一遍。走到哪、过没过，一笔一笔记在账上。
- 判据是算完的条件：每步挂几条，分三种——程序自己核的（`rule`）、交给 AI 判的（`agent`）、等人拍板的（`human`）。

推进一步用一条命令：

```bash
qtcloud-work order next AI冒烟
```

读作：把 `AI冒烟` 这件工单的下一步交给 AI 做。`workers/` 就是干这件事的那一块。

## 跑一趟：order next AI冒烟

假设账本里有一件工单 `AI冒烟`，引着一张三步的工作流，现在停在第一步「问候」。敲下命令后：

1. 打开工单，看它引哪张工作流、走过哪几步。第一步「问候」没走过，就是下一步。
2. 这一步写着交给 AI，于是把它的现场凑成一段话：工单叫什么、这一步要做什么、报告和日志落在哪、前几笔流水是什么、这一步有哪些判据。
3. 把这段话交给 `pi`（一个命令行 AI）跑。比如让它「在工作区里写一句中文问候」。
4. `pi` 跑完，程序先自己核程序判据：文件在不在、命令通不通。
5. 这一步还有一条交给 AI 判的判据（比如「问候是中文」），于是再让 `pi` 按这条判一遍，答「通过」或「不通过」。
6. 两边都过，就在账上记一笔（这一步过了）；任一边不过，也记一笔（没过）。有等人拍板的判据就不记，停在「等人放行」。
7. 把每一步的结果打到屏幕上。

一句话：这块执行器管的是第 2 到第 6 步，也就是「怎么把一步交给 AI、怎么把结果收回来」。

## 代码在哪

- `workers/agent.rs`——执行器 `AgentWorker`，上面这套流程的四个动作都在这儿，另加动作出口 `order_next`。逐法说明见 [agent](agent.md)；
- `adapters/pi.rs`——跟 `pi` 打交道：起进程、把输出收成一行、从回答里认「通过 / 不通过」。见 [adapters](../adapters/pi.md)。

给 AI 的那两段话（做什么、按什么判）本身不在这儿，在 `src/prompts.rs`；执行器只把工单现场凑成那两段话要的数据。

## 一条边界，先记住

`AgentWorker` 只拿工作区的路径，不拿工单不放；记账是调工单自己的方法，账本上那一行 JSON（领域事件）由工单聚合自己发。为什么：适配层不替聚合做它自己的事。往下读代码时，看到 `workers/` 里出现 `crate::order::events` 就是越界——现在没有。

## 测试

想跑起来看，`tests/order_next.rs` 是最全的一趟：AI 跑成 / 跑不成、审查过 / 不过、重走追加。三类判据的各种组合在 `tests/criteria_matrix.rs`。
