# 工作云命令行

这份文档是这套能力的正本：命令面与数据字段以它为准，测试照它写（文档驱动），实现让测试变绿（测试驱动）。这一轮不对接 provider，先在本地把做法做出来；实验室（`examples/default/`）那份是原型，不往上搬。

## 动作面

```
qtcloud-work catalog [--json 文件]           看目录：按名索引工作区里的资产
qtcloud-work audit [--json 文件] [--make]    审计：资产表与实际双向对账，--make 补建缺的格子
qtcloud-work find <名字> [--show]            按名找文档：认文件名与篇内标题
qtcloud-work material [路径…] [--json]       看材料：类型、内容、来源、时间

qtcloud-work workflow --list                 有哪些工作流、各串了哪些步骤
qtcloud-work workflow <名字>                 看这条工作流的步骤、谁执行、怎么算完
qtcloud-work workflow --new <名字> --steps 甲,乙 [--note 一句话]
qtcloud-work workflow <名字> --export <文件>  原样带走
qtcloud-work workflow --import <文件> [--as 名字]

qtcloud-work task --list                     有哪些任务、跑哪条工作流、下一步
qtcloud-work task --new <名字> --workflow <工作流>
qtcloud-work task <名字>                     步骤状态与流水
qtcloud-work task <名字> --next              走下一步
qtcloud-work task <名字> --done <步骤> [--note 一句话]
qtcloud-work task <名字> --journal <一段话>   记这次工作的来龙去脉
```

全局三个位置：`--root` 工作区、`--data` 数据仓（任务与产物落这里）、`--workflows` 工作流目录（默认跟在数据仓里）。

## 数据

**工作流**是一份 YAML，文件名即工作流名：顶层 `description` 与 `steps`；步骤四个字段 `name`、`description`、`executor`、`criteria`，`executor` 取 `agent` 或 `human`（缺省 `agent`）；判据三个字段 `executor`、`description` 与判法。不认识的字段、缺必填字段、取值越界，一律报错。

**任务**是一份 YAML，文件名即任务名：`name`、`start`（开工时间）、`workflow`（跑哪条）、`root` / `data` / `workflows`（这次执行自带的运行上下文）、`log`（流水）。流水一条四项：`at`、`step`、`detail`、`ok`，只增不改；步骤是否走过由流水读出。

**产物**按类型分家：报告 `artifacts/report/<任务>.md`（程序维护「执行记录」与「闸门项」两节，其余归人）、日志 `artifacts/journal/<任务>.md`（叙事）。正式仓在领域侧按人分：`data/report/iGuo/`、`data/journal/iGuo/`。

**材料**四个字段：类型、内容、来源、时间，落在它所在的那一格；阶段由位置承担。

## 判据

判据按主体分三类。`rule` 由程序按字段判，四种判法任选其一：`path` 路径存在、`absent` 路径不存在、`file` 与 `contains` 成对（文件含这段文字）、`run` 命令退出码为零。`agent` 由智能体照判准逐条判。`human` 不跑，进报告的「闸门项」等人拍板。

两条规矩：判据不许由执行那一步的智能体自己写或改；程序每走一步都会写回报告与任务，所以判据里别拿「仓库干净」当条件，要看具体对象。

## 用例

**一、起一件任务并走一步。** 场景：有一条工作流，要按它做一次。期望：`task --new` 落下任务文件（记下工作流与运行上下文）并建好产物骨架；`task --next` 把这一步交给智能体执行，跑完由程序逐条核机械判据、记一笔流水（标明执行者）、刷新报告的「执行记录」与「闸门项」；判据全过则步骤算走过。

**二、语境条目进材料。** 场景：语境里新到若干条口语流水，要落成个人档案的材料。期望：拉语境后逐条列出并认归属；每条粗加工成「标签：内容」的小节写进 `materials/<分类>/index.md`（分类目录不在就新建）；已进材料的条目从语境日期文件里删净，日期文件留空、目录保留；档案仓与语境仓各自提交推送，再回工作区更新两个指针。已有内容的条目不再重复写入。

**三、课程档案比对。** 场景：个人档案的课程草稿与课程研发档案要对照一次。期望：两边档案的定位由机械判据核对；对照结果写进报告 `data/report/iGuo/compare-course-profile.md` 的「比对」一节，结论写进「结论」一节；「创始人点头」作为人的闸门挂进报告，等人拍板。

**四、判据写不对时。** 场景：末条判据原写成「工作区里两个指针都已记录」，真跑起来判不过。期望：判不过的原因是程序自己的记账总在提交之后落笔、仓库必然带脏；改法是看具体对象（子模块指针，忽略内容脏），改完必须真跑一遍才算数。

**五、工作流带走与复用。** 场景：换机器、换数据仓、换工作区。期望：`--export` 原样存一份、`--import` 导回来逐字段一致；重名挡住，`--as` 换名放行；不是工作流的文件被 schema 挡住。

**六、运行上下文随任务走。** 场景：任务与工作流目录、数据仓不在同一处。期望：任务文件记下 `root`、`data`、`workflows`；此后只写数据仓（「任务在哪」的指针）就能开这件任务，工作区与工作流目录不写参数就用记着的，不靠全局配置。

**七、材料的四字段能自动填。** 场景：给一批真实文件。期望：类型取扩展名、内容取正文、来源取上级目录加文件名、时间取该文件所在仓库的首次提交日期（退回文件名里的日期）；原始与材料之分由资产位置承担，不占字段。
