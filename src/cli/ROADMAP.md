# 路线图

本文概述重构的动机、阶段划分与验收标准；改动范围与逐条判据见 [TODO.md](TODO.md)。

## 背景

规格已修订为四篇：工作流（`docs/specification/process/workflow.md`）、工作步骤（`work-step.md`）、工单（`work-order.md`）、工作记录（`work-record.md`）。实验室 v2（`examples/default/apps/qtcloud-work-lab-v2`）按新规格完成了一次真实流程的验证。正式版 CLI 仍采用 v1 模型：`task` 携带 `log` / `gates` / `artifacts` 字段，工作流定义不含凭证，执行位置记入任务文件。本轮重构将实验室验证所得的经验落实到正式版。

问题的共同根源是：应当由推导得出的结论被落成了字段，应当由外部装载的位置被记进了模型。

- **模型与规格不一致**：`Task` 同时承担工单封面与工作记录账本两类职责，规格中对应两篇；`gates` 可由定义中 `human` 判据的所在步骤推导得出，却作为字段存储；进度与完结按 `·审` / `·判` 后缀投票判定，未与流水逐站对账。
- **位置进入模型**：工单文件记录 `root` / `data` / `workflows` 三处位置，跨机器或迁移仓库后即失效；规格已确定位置由平台装载、不进入模型。
- **账本与产物同处**：程序每次执行都向仓库写入账本。账本属于本机运行数据，报告与日志属于内容产物，两者应分离存放。

由此产生的具体问题（逐条出处见 TODO 的「为什么」）：定义中须为每条工作流、每个步骤手工编制 UUID；流水不可修改、不具备追加幂等；人的放行仅存在于流水，报告与定义均不可见，导致后续步骤的执行者与复查者重复执行已裁决的内容；工作流描述中抄录了会变化的分类目录，材料库扩充后条目无法归类。

## 目标

1. 模型对表：`Task` 拆分为工单与工作记录；`gates` 不再作为字段存储；封面落笔即封、流水只增不改；进度与完结仅由推导得出。
2. 凭证分层：定义不写 `id`，按「工作区 id + 名字」推导生成（uuid5，命名空间固定，各平台计算结果一致）；工单与工作记录的凭证由程序生成。
3. 位置归位：账本归 CLI（缺省 `$XDG_DATA_HOME/qtcloud-work/workspaces/<工作区键>/`），产物归工作区（`<工作区根>/artifacts`），位置全部由启动参数装载。
4. 命令面对齐规格端点表：`workflow …` / `order …` 采用动词式；三类领域事件写入 JSONL。
5. 文档与测试同步：用例、接口参考、开发指南、数据迁移与变更记录全部对齐新模型。

## 阶段规划

| 阶段 | 内容 | 验收标准 |
| :-- | :-- | :-- |
| 一 · 定名与模型对表 | 先确定 `task` 的新名称，再拆分工单与工作记录、删除 `gates` 字段、建立凭证与流水规则、补充工作区身份 | 模型中不存在 `log` / `gates` / `start`；`records` 只增不改；进度由 `records` 对照定义推导 |
| 二 · 位置 | 账本缺省位置改为 XDG 工作区键、新增 `--artifacts`、删除工单中的三处位置 | 缺省 `--root` 时仍可创建工单；只读动作不在任何根上创建文件 |
| 三 · 定义 | 落点引用按产物落点展开；定义不抄录其他来源的事实；`check` 补充两条规则 | 现有定义不做修改即可读取并通过核对 |
| 四 · 执行 | 命令面改为动词式、提示词附带流水、规格引用改指新篇 | 命令面与规格端点表一一对应 |
| 五 · 事件 | `WorkflowCreated` / `WorkOrderCreated` / `WorkRecorded` 写入 JSONL | 同 `id` 重放不会重复落账 |
| 六 · 文档与测试 | 用例、接口参考、开发指南、数据迁移与门禁 | 两侧用例集合一致；单文件不超过 250 行；与 studio 对表四项一致 |

阶段一、二是后续各段的基础：模型与位置未确定，后续改动均需返工。阶段五、六须待字段确定后进行，其后可并行。

每段完成后执行以下命令，全部通过方视为完成：

```bash
cargo fmt --check && cargo clippy --all-targets --locked -- -D warnings && cargo test --locked
sh scripts/validate-usecases.sh && sh scripts/validate-line-count.sh
```

发布前另行执行 `scripts/validate-changelog.sh` 与 `scripts/validate-version.sh`；命令面变更属于破坏性变更，随版本号发布。

## 当前状态

尚未开始实施，v1 模型维持可用；待办已细化（见 [TODO.md](TODO.md)），实验室 v2 可作为行为对照。

当前阻塞：阶段一的第一步是为「工单 / 工作记录」这一对概念确定中文名与目录名——现名 `task` 与规格不符，且命名由用户决定。名称确定后阶段一方可实施，后续各段的文件路径均以该名称为准。

## 与 studio 的关系

新增动作（`order delete`）与改名（`data` 中 `log` 改为 `records`，移除 `start` / `gates`）需在 studio 侧同步；两侧仅比较 `ok` / `columns` / `rows` / `data` 四项，不比较 `lines`。
