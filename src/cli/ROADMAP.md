# 路线图

这一份是给人看的：cli 往哪走、哪些要你拍板。可动手的细节在 [TODO.md](TODO.md)，逐条体检数据在 [STATUS.md](STATUS.md)。

## 目标

cli 是知识工作云的命令行入口：把知识工作做成可执行的编排。内部已按契约分家（原来平铺一层、最长 945 行，现在聚合一目录、最长 240 行），成了一个能独立验证的单元。

再往前不在本仓内部，而在「对外」三面：契约定归属与依赖、文档与实现同构、领域按规格新立的「产物类别」重理平台。这三面都要和 studio、规格、发布线对齐，不由本仓独自定。

## 要你拍板

1. 产物「类别 / 名字」两轴：`Artifact` 纳不纳入类别；落点按类别还是按名字。
2. `Workflow` 的 `name` 与文件名不一致时，挡在工具箱 `validate` 还是本侧 `load`。
3. CLI 用词：规格叫「产物类别」，cli 的文档与注释仍写「资产表 / 资产」——跟不跟。
4. 发布线：studio 与 cli 一条线还是两条（cli 那条已开）。
5. IaC 归属：cli 的发布物（crates.io + 三平台二进制）与基础设施归本仓还是平台仓。
6. 依赖许可清单：要不要，细到哪一层。
7. `prompts`：cli 与 studio 两份合一，还是各留一份并写明差异。

## 与 studio

两条命令面是一件事的两侧，改名与版本同批走；对表只比 `ok` / `columns` / `rows` / `data`，不比 `lines`。
