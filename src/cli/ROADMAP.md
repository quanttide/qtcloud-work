# 路线图

给人看的一页：cli 往哪走、哪些要人拍板。可直接动手的细节在 [TODO.md](TODO.md)，逐条体检数据在 [STATUS.md](STATUS.md)。

## 方向

`cli` 要成为**契约下的可独立验证单元**：按聚合分目录、单文件 ≤250 行、文档与实现同构——每个聚合是一个能独立验证的小软件。改名与版本与 studio 同批走。

## 已完成

- `find` → `search`；`src/` 按聚合 / 服务 / 适配分家；三个长文件拆开（最长 240 行）
- 端侧适配：两侧同号 `quanttide-work 0.1.0-beta.6`；与 studio 对表 24/24
- 任务进度条；规格立「产物类别」，平台 `kind` → `category`

## 要人对齐的

| 事 | 选哪边 |
| :-- | :-- |
| **「类别 / 名字」两轴重理** | `Artifact` 纳不纳入类别；落点按类别还是按名字。规格已定：类别是人可调的归类，名字是具体如《量潮知识工作报告》 |
| **`name` 与文件名不一致挡在哪** | 工具箱 `validate` 收文件名核一致 / 本侧 `load` 里挡——规范层面的取舍，先定规矩 |
| **CLI 用词：`资产` → `产物类别`** | 规格已立「产物类别」，cli 的文档与注释仍写「资产表 / 资产」——跟不跟 |
| **`prompts` 口径** | cli 与 studio 两份合一，还是各留一份并写明差异 |
| **依赖许可清单** | 要不要，细到哪一层（政策） |
| **IaC 归属** | 发布物（crates.io + 三平台二进制）与基础设施归本仓还是平台仓 |
| **行数门禁** | 单文件 ≤250 行进不进 CI |
