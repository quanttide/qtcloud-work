# 路线图

这份讲 cli 往哪走、怎么算走到。能直接动手的细节见 [TODO.md](TODO.md)，逐条带判据；体检数据见 [STATUS.md](STATUS.md)。

## 为什么做

cli 是知识工作云的命令行入口：工作流定义干什么、任务记这一次怎么走、判据判算不算完。命令面与内部结构这一关已经过了——`src/` 按聚合 / 服务 / 适配分家，单件都在 250 行门限内，约定落在 `src/CONVENTIONS.md`。

往前不是继续搬结构，是把这份结构守住：宣称的能力有测试坐实、文档画的是同一棵树、依赖与行数有门禁挡着。守不住，分家只是这一次的整理，下次改动照样糊回去。

对外还有一面：cli 与 studio 是同一件事的两侧，共用工具箱 `quanttide-work`；规格新立的「产物类别」要重理平台。这一面的事实源在规格与平台，本仓只承接自己那一段。

## 分几段走

三段，前面的先做。

| 段 | 做什么 | 怎么算完 |
| :-- | :-- | :-- |
| 一 · 坐实 | 补流水落点的测试（`Task::artifact("log")` 等于任务文件本身）；用例对账去空转（`docs/user-guide/` 补「## 用例」，测试按用例标出处） | `validate-usecases.sh` 对出的两行用例号非空且相等；新测试在、跑绿 |
| 二 · 同构 | 重写 `docs/dev-guide/layers.md`（改成三类落点图，去掉「拟建」）；`docs/api-references/` 分命令参考与概念参考 | 文档结构与 `src/` 一一对得上；参考目录不再混两类 |
| 三 · 守门 | 许可清单（要不要、细到哪一层见「等定规」）；行数门禁：`src/**/*.rs` 超 250 行即红 | `Cargo.toml` 每个依赖都在清单里；超阈能拦 |

**每段做完都跑**（缺一不算完）：

```bash
cargo fmt --check && cargo clippy --locked && cargo test --locked
sh scripts/validate-usecases.sh
```

### 顺序依据

- **先坐实，再同构**：用例号对不上，「测试绿」说明不了什么；文档同构要引的正是这套用例号。
- **先同构，再守门**：门禁是把已经说清的规矩自动化。规矩没写进文档就先立门禁，挡住的是旧规矩。
- **跨仓的等定规**：类别与名字、`name` 与文件名、用词、`prompts`、发布线、IaC 改的都是两侧或三仓的契约，本仓只有一侧，先斩会破对表。

## 等定规（定了再落）

要人拍板的事都在 [TODO.md](TODO.md) 的「等定规」一节：产物「类别 / 名字」两轴、`name` 与文件名一致、cli 用词跟不跟规格、`prompts` 两份合不合、发布线一条还是两条、IaC 归属、依赖许可清单要不要。
