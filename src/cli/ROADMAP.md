# 路线图

这一份是给人看的：为什么做、做到哪、怎么算做完。改哪些文件、每条怎么核，见 [TODO.md](TODO.md)。

## 为什么做

规格已换成四篇——`docs/specification/process/workflow.md`、`work-step.md`、`work-order.md`、`work-record.md`；实验室 v2（`examples/default/apps/qtcloud-work-lab-v2`）照新规格跑通了真流程，把坑踩过一遍。正式版 CLI 还停在 v1 的模型：`task` 带 `log` / `gates` / `artifacts`，工作流不带凭证，位置记进任务文件。这一轮是把实验室的经验落到正式版上。

根子是同一处：**该推导的落了字段，该装载的记进了模型**。

- **模型对不上规格**：`Task` 一个类型包办封面与账本，规格里这是两篇（工单 + 工作记录）；`gates` 本可由定义里 `human` 判据的所在站推出，却落了字段；进度与完结按 `·审` / `·判` 后缀投票，不从流水对账。
- **位置进了模型**：工单文件记着 `root` / `data` / `workflows`，换机器、挪仓库就断——规格已定位置由平台装载、不进模型。
- **账本与产物同处**：程序每跑一趟就往仓库写账本。账本是这台机器上的账，报告与日志是内容，混在一处两边都不干净。

派生出的具体坑（实验室原话，逐条见 TODO 的「为什么」）：定义里要给每条工作流、每个步骤凭空编 UUID；流水改不动、不幂等；人的放行只落在流水里，报告与定义都看不到，下一步的执行者与复查者白跑一趟；工作流描述里抄了会变的分类目录，材料库一长就落不进去。

## 目标

1. **模型对表**：`Task` 拆成工单与工作记录；`gates` 不落字段；封面落笔即封、流水只增不改；进度与完结只推导。
2. **凭证分层**：定义不写 `id`，按「工作区 id + 名字」现算（uuid5，命名空间钉死，各平台算得一样）；工单与工作记录由程序发号。
3. **位置归位**：账本归 CLI（`$XDG_DATA_HOME/qtcloud-work/workspaces/<工作区键>/`），产物归工作区（`<工作区根>/artifacts`），位置全由启动参数装载。
4. **命令面与规格端点一一对应**：`workflow …` / `order …` 走动词式；三件领域事件落 JSONL。
5. **文档与测试跟上**：用例、接口参考、开发指南、数据迁移与变更记录都对到新模型。

## 六段怎么走

| 段 | 做什么 | 怎么算完 |
| :-- | :-- | :-- |
| 一 · 定名与模型对表 | 先定 `task` 改成哪一对名字，再拆工单与工作记录、删 `gates`、立凭证与流水规矩、补工作区身份 | 模型里没有 `log` / `gates` / `start`；`records` 只增不改；进度由 `records` 对照定义推导 |
| 二 · 位置 | 账本缺省落 XDG 工作区键、新增 `--artifacts`、删工单里的三处位置 | 不给 `--root` 也起得了单；只读动作不在任何根上建文件 |
| 三 · 定义 | 落点引用按产物落点展开；定义不抄别处拥有的事实；`check` 补两条 | 旧定义一个字不改读得进、check 得过 |
| 四 · 执行 | 命令面改动词式、提示词带上流水、规格引用改指新篇 | 命令面与规格端点表一一对应 |
| 五 · 事件 | `WorkflowCreated` / `WorkOrderCreated` / `WorkRecorded` 落 JSONL | 同 `id` 重放不二次落账 |
| 六 · 文档与测试 | 用例、接口参考、开发指南、数据迁移与门禁 | 用例两边集合相等；单文件 ≤250 行；与 studio 对表四样一致 |

段一、二是地基：模型与位置定不下来，后面每段都得跟着返工。段五、段六要等前面的字段定死，之后彼此可并行。

**每段做完都跑这两条**（缺一不算完）：

```bash
cargo fmt --check && cargo clippy --all-targets --locked -- -D warnings && cargo test --locked
sh scripts/validate-usecases.sh && sh scripts/validate-line-count.sh
```

发布前另跑 `scripts/validate-changelog.sh` 与 `scripts/validate-version.sh`；命令面变更属破坏性变更，随版本号走。

## 与 studio 的关系

新增动作（`order delete`）与改名（`data` 里 `log` → `records`、去掉 `start` / `gates`）要在 studio 侧同步；两侧只比 `ok` / `columns` / `rows` / `data` 四样，不比 `lines`。
