# 路线图

这一份是给人看的：为什么做、做到哪、怎么算做完。细节改哪些文件见 [TODO.md](TODO.md)，逐条体检数据见 [STATUS.md](STATUS.md)。

## 为什么做

cli 已经能用也能发：命令面四组齐、三轴文档齐、用例对账与发布纪律都在。但按软件工程契约量一遍，`src/` 曾是**平的一层**：聚合件（`task` `workflow` `material` `catalog`）、服务件（`search` `audit`）、适配件（`cli` `help` `prompts` `health`）同层并列，最长文件涨到 **945 行**——没有边界的地方，谁都往里加。

契约的终态是**分聚合**：每个聚合就是一个可独立验证的小软件——结构给验证单元、用例给判据、人审一个聚合而不是审整个工具。

## 目标

1. **cli 成为契约下的可独立验证单元**：按聚合分目录、服务与适配各归其位、单文件 ≤250 行
2. **对外对齐**：依赖许可清单、两侧工具库版本同步、IaC 归属
3. **文档与实现同构**：`docs/dev-guide/layers.md` 重写成三类的落点图

## 交付哪些模块

**聚合**（有自己的定义：身份、生命周期、字段规矩）

| 目录 | 管什么 |
|---|---|
| `task/` | 任务：状态推导、走一步、流水、报告、日志 |
| `workflow/` | 工作流：YAML 读写、严格 schema、五个动作 |
| `catalog/` | 目录：扫描成名字索引（条目与快照语义是它自己的定义） |
| `artifact/` | 产物类别的清单：有哪些类别、各落在哪——定义即规范 |
| `material/` | 材料：类型 / 内容 / 来源 / 时间，阶段由位置承担 |
| `workspace/` | 工作区：三处位置与落点 |

**领域服务**（没有自己的定义，跨聚合只做一件事）：`search/`（按名找文档，用 `catalog` 的名字索引）、`audit/`（审计工作区）。

**适配**（边界外的东西与入口）：`cli.rs`（入口与发射）、`cli/`（子命令分派与发射）、`help.rs`、`prompts.rs`、`health.rs`。

## 与 studio 的关系

两条命令面是一件事的两侧，**改名与版本必须一起走**；`parity.sh` 只比 `ok` / `columns` / `rows` / `data`，不比 `lines`。

## 边界外（越界但相关，需要你拍板）

1. **「类别 / 名字」两轴重理**：`Artifact` 纳不纳入类别；落点按类别还是按名字——规格已定：类别是人可调的归类，名字是具体如《量潮知识工作报告》。
2. **CLI 用词 `资产` → `产物类别`**：规格已立「产物类别」，cli 的文档与注释仍写「资产表 / 资产」——跟不跟。
3. **`name` 与文件名不一致挡在哪**：工具箱 `validate` 收文件名核一致，还是本侧 `load` 里挡。
4. **依赖许可清单**：要不要，细到哪一层。
5. **IaC 归属**：发布物（crates.io + 三平台二进制）与基础设施归本仓还是平台仓。
6. **行数门禁**：单文件 ≤250 行进不进 CI。
7. **`prompts` 口径**：cli 与 studio 两份合一，还是各留一份并写明差异。
