# 任务（执行侧）

任务是工作流的**一次执行实例**。工作流是定义（要变成什么样），任务的记录（这一次怎么走）。

## 文件

一个任务一个文件，落在数据仓的 `tasks/<任务名>.yaml`。

| 字段 | 含义 |
|---|---|
| `name` | 任务名 |
| `start` | 开工时间 |
| `workflow` | 跑的是哪条工作流 |
| `root`／`data`／`workflows` | 三处位置记在任务里，后续动作不必重复传 |
| `log[]` | 流水 |
| `gates[]` | 闸门项 |
| `products` | 产物落点 |

## 流水

一条流水＝`at`（时间）、`step`（步骤名）、`detail`（一句话）、`ok`（过没过）。步骤名带三种后缀：

| 后缀 | 谁记的 | 含义 |
|---|---|---|
| 无 | 执行者 | 这一步走了一遍 |
| `·审` | AI | 按 `agent` 判据审这一步 |
| `·判` | 机器 | 按 `rule` 判据判这一步 |

一步算不算走完，看它**最近一次**尝试——先前的失败不该压着后来的通过。

## 闸门与产物

- **闸门**：`executor: human` 的判据，记进 `gates`；人没点头，这一步不算过
- **产物**：报告、日志、流水三个落点。落点由任务声明，内容谁写谁定；**程序不往产物里写一个字**

## 命令行

列任务与下一步：`task --list`；起一件：`task --new <名字> --workflow <工作流>`；看流水：`task <名字>`；
走下一步：`--next`；人为记一步：`--done <步骤> --note 一句话`；收叙事：`--journal`。

## 界面上

任务页右栏就是这个模型：状态与进度、闸门、产物、流水；动作只留 `--next` 与 `--done` 对应的两个。
