# 量潮工作云工作台（原型）

Flutter Web 客户端 `src/studio` 的界面参照，也是命令行 `qtcloud-work` 的图形入口。

一条底线：**界面上出现的东西，命令行里都做得到；命令行里没有的动作，这里也不出现。**

## 怎么分

| 目录 | 装什么 | 实现 |
|---|---|---|
| [screens/](screens/task.md) | 三个页面：任务、流程、设置 | [`lib/screens/`](../lib/screens) |
| [views/](views/sidebar.md) | 页面里可复用的块：侧栏、顶栏、对话、状态面板、步骤链、判据面板、定义态 | [`lib/views/`](../lib/views) |
| [models/](models/workflow.md) | 界面背后的数据：工作流（定义侧）、任务（执行侧）、三处位置 | [`lib/models/`](../lib/models) |

命令行客户端在 [`lib/cli/`](../lib/cli)：只读统一信封，不自己解析工作流与任务文件的原文。

每篇 `.md` 都配一份伴生文件：**屏与视图配 `.html`**（自带样式，可单独在浏览器里打开看），
**模型配 `.json`**（真实样例，从仓里的工作流定义与任务文件转来）。

`index.html` 是可点的整合原型（单文件跑起来，无外部依赖）；`screens/` 与 `views/` 的描述与它一一对应。

界面实现落在 `../lib`：`models/` 是这几个模型，`cli/` 是命令行客户端（只读统一信封，不自己解析文件原文）。

## 三屏

| 屏 | 看什么 | 文件 |
|---|---|---|
| 任务 | 一次执行实例 | [screens/task.md](screens/task.md) |
| 流程 | 一条定义 | [screens/flow.md](screens/flow.md) |
| 设置 | 三处位置与探活 | [screens/settings.md](screens/settings.md) |

## 界面不做的事

- 不暂停、不取消、不重试——命令行没有这三个动词，任务是一步一步走的
- 不洗上下文、不留快照——那不是这套东西的概念
- 没有工作流版本历史，也没有「发布」按钮——发布是某条流程里的一步，不是界面动作
- 不把任务另存成工作流——要复用就改定义，或 `workflow --new` 起一条新的

## 界面这一层还没读进来的

界面现在跑的是 studio 自己那套实现（`lib/core`），不再起子进程调命令行。还差的是「读进来显示」：

| 差哪样 | 现在界面显示什么 | 卡在哪 |
|---|---|---|
| 判据的逐条文字 | 「机器 N 条 / AI N 条 / 人 N 条」 | 定义文件里有；要显示每条得让界面直接读定义，或让 `workflow <名字>` 把它放进 `rows` |
| 定义原文 | 定义文件的位置 | 同上：原文在文件里，界面还没展开 |
| 对话 | 对话栏摆着但不可发 | 对话这一路还没接（谁跟谁说话、话记在哪，得先定） |

## 数据从哪来

界面不自己存东西，三处位置都由命令行给：工作区、数据仓（任务与产物草稿）、工作流目录。
任务文件里装的是流水、闸门项与产物落点；报告与日志是产物，跟任务无从属关系。
