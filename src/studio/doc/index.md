# 量潮工作云工作台（原型）

Flutter Web 客户端 `src/studio` 的界面参照，也是命令行 `qtcloud-work` 的图形入口。

一条底线：**界面上出现的东西，命令行里都做得到；命令行里没有的动作，这里也不出现。**

## 三页

| 页 | 看什么 | 对应命令行 |
|---|---|---|
| 任务 | 一次执行实例：左边对话定目标，右边这次走成什么样 | `task --list`、`task --new`、`task <名字>` |
| 工作流 | 一条定义：左边对话改流程，右边看步骤与判据 | `workflow --list`、`workflow <名字>`、`--check`、`--export`、`--import`、`--new` |
| 设置 | 三处位置与已部署 provider 的探活 | `--root`、`--data`、`--workflows`、`health` |

## 任务页

左边是对话：先出流程草案（步骤清单，每步标执行者与判据条数），人确认后才跑。

右边是这次走成什么样：

- **状态**：`运行中 · 3 / 6`、当前步骤、进度条、关联工作流（点开回工作流页）
- **闸门**：标着「留给人」的那一步，等人放行
- **产物**：报告、日志、流水三个落点——内容谁写谁定，程序不往产物里写一个字
- **流水**：最近几条（时间／步骤／一句话）；步骤名带 `·审` 的是 AI 审查，带 `·判` 的是机器判据
- **动作**：`走下一步`（`--next`）、`记一步`（`--done --note`）；⋯ 里是`记日志`（`--journal`）、`导出结果`（`--out`）、`看 JSON`（`--json`）、`干跑`（`--dry-run`）

## 工作流页

左边对话（改流程、问判据），右边「步骤」与「定义」两态。

**步骤**：竖着一串，一步接一步。每步显示名字与「执行者 · N 条判据」，按执行者上色（AI／机器／人）。
点一步，下面列出这步的全部判据，每条标明谁判。

**定义**：这条工作流的 YAML 原文——`steps` 里每步的 `executor` 与 `criteria`。定义写成什么样，
界面就显示成什么样；不存在第二套语言。

顶栏：`起一件任务`（`task --new --workflow <这条>`）；⋯ 里是新建、检查、导出、导入、列表。

## 设置页

工作区（`--root`）、数据仓（`--data`）、工作流目录（`--workflows`），以及已部署 provider 的探活（`health`）。

## 界面不做的事

- 不暂停、不取消、不重试——命令行没有这三个动词，任务是一步一步走的
- 不洗上下文、不留快照——那不是这套东西的概念
- 没有工作流版本历史，也没有「发布」按钮——发布是某条工作流里的一步，不是界面动作
- 不把任务另存成工作流——要复用就改定义，或 `workflow --new` 起一条新的

## 数据从哪来

界面不自己存东西，三处位置都由命令行给：工作区、数据仓（任务与产物草稿）、工作流目录。
任务文件里装的是流水、闸门项与产物落点；报告与日志是产物，跟任务无从属关系。
