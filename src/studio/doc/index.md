# 量潮工作云工作台（原型）

Flutter Web 客户端 `src/studio` 的界面参照，也是命令行 `qtcloud-work` 的图形入口。

一条底线：**界面上出现的东西，命令行里都做得到；命令行里没有的动作，这里也不出现。**

## 怎么分

| 目录 | 装什么 |
|---|---|
| [screens/](screens/task.md) | 三个页面：任务、流程、设置 |
| [views/](views/sidebar.md) | 页面里可复用的块：侧栏、顶栏、对话、状态面板、步骤链、判据面板、定义态 |
| [models/](models/workflow.md) | 界面背后的数据：工作流（定义侧）、任务（执行侧）、三处位置 |

`index.html` 是可点的整合原型（单文件跑起来，无外部依赖）；`screens/` 与 `views/` 的描述与它一一对应。

## 三屏

| 屏 | 看什么 | 文件 |
|---|---|---|
| 任务 | 一次执行实例 | [screens/task.md](screens/task.md) |
| 流程 | 一条定义 | [screens/flow.md](screens/flow.md) |
| 设置 | 三处位置与探活 | [screens/settings.md](screens/settings.md) |

## 界面不做的事

- 不暂停、不取消、不重试——命令行没有这三个动词，任务是一步一步走的
- 不洗上下文、不留快照——那不是这套东西的概念
- 没有工作流版本历史，也没有「发布」按钮——发布是某条流程里的一步，不是界面动作
- 不把任务另存成工作流——要复用就改定义，或 `workflow --new` 起一条新的

## 数据从哪来

界面不自己存东西，三处位置都由命令行给：工作区、数据仓（任务与产物草稿）、工作流目录。
任务文件里装的是流水、闸门项与产物落点；报告与日志是产物，跟任务无从属关系。
