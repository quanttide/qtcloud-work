# 路线图

这一份是给人看的：为什么做、做到哪、怎么算做完。细节改哪些文件见 [TODO.md](TODO.md)，逐条体检数据见 [STATUS.md](STATUS.md)。

## 为什么做

studio 现在能干活：三屏七块齐、点了真的会动、对话通了；界面跑自己那份实现，与命令行算出来的是同一个结果（`parity.sh` 24 条全一致）。

但按软件工程契约量一遍，有三处硬伤：

- **命名**：`lib/widgets/` 那一层按 Bloc 家法该叫 `views`——`doc/` 已经叫 views，同一层两个名字
- **混用**：`repositories/local/` 里聚合名（tasks、workflows、task_run）与职能名（dispatch、paths、yaml、environment、fs、host）挤在同一层——这是契约里唯一的硬禁形态
- **两套实现**：`client.dart`（起命令行）与 `local/`（自己算）并存，同一件事两份实现

根因是**分层阶段没有强制点**：文件不回答「这属于哪个聚合」，谁都可以往里加，于是最长的文件涨到 378 行（`tasks.dart`）。契约的终态是分聚合——**每个聚合就是一个可独立验证的小软件**：结构给验证单元、用例给判据、人审一个聚合而不是审一整个软件。一坨没法独立验证，反馈只能靠事后返工。

## 目标

1. **studio 成为契约下的一个可独立验证单元**：目录按聚合、单文件 ≤250 行、界面只有一套实现
2. **对外对齐平台契约**：路由、`dart format` 门禁、依赖许可清单、CanvasKit 自托管
3. **文档与工作流跟上**：`doc/` 三轴补齐、工作流判据与现状一致

## 交付哪些聚合（段四的靶子）

`lib/repositories/local/` 按聚合重排，交付这些目录：

| 聚合目录 | 管什么 | 现状 |
|---|---|---|
| `workflow/` | 工作流定义：列表、看一件、核对定义、导出、导入 | 已有（`workflows.dart` 316 行） |
| `task/` | 任务：列表、新建、看一件、走下一步、记一步、收日志 | 已有（`tasks.dart` 378 + `task_run.dart` 279） |
| `material/` | 材料 | 命令面已有、界面侧未搬 |
| `catalog/` | 目录清单 | 命令面已有、界面侧未搬 |
| `audit/` | 审计 | 命令面已有、界面侧未搬 |
| `find/` | 按名找文档 | 命令面已有、界面侧未搬 |
| `workspace/` | 三处位置与环境 | 已有（`paths.dart` + `environment*`） |

不按聚合的那些收进一处 **`platform/`**：命令面（`dispatch`）、导览（`help`）、判据执行（`rules`）、给智能体的话术（`prompts`）、YAML 解析、平台读写（`fs/`、`host/`）。

**界面那一侧不按聚合**：`views/`（可复用的块）与 `screens/`（三屏）按界面职责分——聚合约束的是软件内部那一侧，不是界面。

验收：上述目录都在；`local/` 下不再有散落的单件；单文件 ≤250 行。

## 七段怎么走

| 段 | 做什么 | 怎么算完 |
|---|---|---|
| 一 · 正名 | `lib/widgets/` → `lib/views/` | 目录名对；`flutter analyze`、`flutter test`、`parity.sh` 全绿 |
| 二 · 清混用 | `local/` 里聚合名与职能名不再同层 | `ls local/*.dart` 只剩一种维度；聚合名单进约定文件 |
| 三 · 收敛实现 | 删掉起命令行那层，界面全走 `local/` | `client.dart` 不在；`parity.sh` 24 条仍一致；studio 自己能干完 |
| 四 · 转聚合 | 拆长文件、按聚合重排；约定集中一处 | 单文件 >250 行的为零；**行为不变**（测试与对表全绿） |
| 五 · 契约对齐 | 路由、`dart format`、CanvasKit、依赖清单、IaC 归属 | 每条各有判据，见 TODO 段五 |
| 六 · 文档与工作流 | 补 `doc/` 欠账、重定 `doc/models/`、对齐工作流判据 | doc 三轴与 `lib/` 一一对得上 |
| 七 · 发布线 | 定 studio 与 cli 一条线还是两条线，开 `studio/v*` | 版本号由创始人拍板 |

段一、二是零风险的整理，先做；段三是工作流 `code-implement-studio` 原定的「交接」，做完 studio 才算不依赖命令行；段四在段三之后（同一批文件，别来回改）。

**每段做完都跑这三条**（缺一不算完）：

```bash
flutter analyze && flutter test
sh scripts/parity.sh
```
